# Black Friday Intelligence Egypt

مراقب أسعار سحابي يعمل على **GitHub Actions** حتى والكمبيوتر مغلق. الأولوية لملابس وأحذية الأسرة في مصر. هذه نسخة عملية محدودة المصادر، وليست بحثًا شاملًا لكل السوق أو التطبيقات.

## التشغيل الحالي

- Python 3.12، دون مكتبات خارجية أو اشتراك خادم.
- جدول كل 15 دقيقة تقريبًا: الدقائق 7 و22 و37 و52 من كل ساعة UTC. هذه مواعيد طلب التشغيل وليست ضمانًا للتنفيذ؛ قد تتأخر أو تسقط جولات عند ضغط GitHub. يمكن أن تفوت عروض Flash Sale القصيرة.
- يبدأ تلقائيًا بعد رفع الكود إلى `main`؛ يبدأ جمع الأسعار دون Telegram حتى إضافة الأسرار.
- أول قراءة تبني خط أساس فقط. التنبيه عند انخفاض **15% أو أكثر** مقارنة بأقل سعر متوفر رصده النظام خلال آخر 30 يومًا، لنفس المنتج والمقاس واللون. لا نستعمل السعر المشطوب لإثبات الوفر.
- قراءة ثانية من صفحة بيانات المنتج للتحقق من السعر والتوفر قبل الإرسال.
- `data/state.json` يحتفظ بالتغيرات ونقاط يومية لمدة 30 يومًا. `data/status.json` يبين وقت آخر جولة وحالة كل مصدر؛ وقت كل قراءة UTC.
- منع تكرار نفس تنبيه الاختيار والسعر لمدة 90 يومًا. الحد الأقصى 5 رسائل في الجولة؛ المرشح غير المرسل ينتظر حتى 6 ساعات وتُراجع صلاحيته قبل الإرسال.
- الأسعار أسعار عرض قبل الشحن، ولا تشمل بالضرورة كوبونات السلة أو التطبيق أو عروض الحساب. لا ننفذ شراء ولا ندعي أنه الأرخص في مصر.

كل مصدر مفعّل يقرأ **أول صفحتين، بحد أقصى 100 منتج**، بكل الاختيارات التي يعيدها المصدر. هذا ليس الكتالوج الكامل، ولا تُضمن ثبات عضوية هذه الصفحات أو ترتيبها. لا تتوفر مراقبة شاملة لكل أحذية الرجالي والأطفال حاليًا. حافظ على المنتجات المهمة عبر `pinned_handles` لكي تظل مراقبة حتى لو خرجت من نافذة الاكتشاف.

السعر المؤكد هنا يعني اتفاق قراءتين من المتجر على نفس الاختيار، وليس تحققًا مستقلًا من السعر النهائي في الدفع. الإعلانات العامة عن خصومات إضافية أو موعد نهاية العرض لا تُلتقط من اللافتات؛ تلتقط النسخة انخفاض سعر المنتج حين يظهر في البيانات. لا تتجاوز الحجب أو CAPTCHA، وتتوقف عن المصدر إن منعت قواعد robots الوصول. فشل مصدر لا يعطّل جمع بقية المصادر، لكنه يجعل الجولة حمراء للتنبيه إلى العطل.

## إعداد GitHub Actions

1. افتح تبويب **Actions**، واسمح بتشغيل الإجراءات إذا ظهر طلب التفعيل.
2. افتح **Settings → Actions → General → Workflow permissions**. اسمح للمراقب بالكتابة إلى المستودع (Read and write permissions) إن كانت سياسة المستودع تمنع الصلاحية المحددة في ملف التشغيل. يحتاج كتابة `data/` للحفاظ على التاريخ ومنع التكرار. إذا حمت قواعد الفرع `main` من كتابة البوت ستفشل خطوة الحفظ؛ راجع القواعد بدل اعتبار التشغيل مكتملًا.
3. افتح **Actions → Egypt Price Watcher → Run workflow → main** لتشغيل جولة يدوية. يجب أن تنجح خطوات الاختبارات وجمع الأسعار وحفظ الحالة.
4. افحص **Summary** و`data/status.json`؛ تاريخ قديم أو حالة `error` تعني أن التغطية غير سليمة. لقطات استعادة الحالة محفوظة أيضًا في Artifacts لمدة 14 يومًا.

الجدول يعمل من الفرع الافتراضي فقط. GitHub قد يعطّل جداول المستودعات العامة بعد 60 يومًا من عدم نشاط المستودع؛ راجع التفعيل عند بدء الموسم. حدود الحساب والتسعير قابلة للتغيير؛ راجع [استخدام GitHub Actions](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions) ولا تفترض تشغيلًا مجانيًا غير محدود.

## ربط Telegram بأمان

1. افتح [BotFather الرسمي](https://t.me/BotFather)، وأرسل `/newbot` واتبع التعليمات. احتفظ بالتوكن لنفسك؛ **لا ترسله في الشات أو ملف أو Issue أو Commit**.
2. افتح البوت الجديد في Telegram واضغط Start وأرسل له رسالة.
3. لمعرفة معرف محادثتك دون لصق التوكن في عنوان المتصفح، شغّل محليًا `python tools/telegram_chat_id.py`. يطلب التوكن بإدخال مخفي ويعرض معرف المحادثة فقط. لا تشغّل هذا السكربت في Actions. إذا كانت نتائج التحديثات فارغة، أرسل رسالة جديدة؛ البوت المستخدم مع webhook قد يحتاج بوتًا منفصلًا.
4. افتح [إعداد أسرار المستودع](https://github.com/eldeebvs-code/black-friday-intelligence/settings/secrets/actions) → **New repository secret** وأضف:
   - `TELEGRAM_BOT_TOKEN`: التوكن من BotFather.
   - `TELEGRAM_CHAT_ID`: معرف المحادثة المقصودة.
5. **Actions → Egypt Price Watcher → Run workflow** واختر `test_telegram = true`. تأكد بنفسك من وصول رسالة الاختبار. لا يمكن اعتبار Telegram جاهزًا قبل وصولها.

الأسرار تُمرر لخطوات الإرسال فقط ولا تُكتب في التاريخ أو تقرير الحالة. عند غيابها يستمر بناء سجل الأسعار دون إرسال. عند فشل الإرسال لا يُسجل التنبيه كمُرسل ويعاد فحص المرشح في الجولة التالية. لا ترسل توكناتك لأي شخص؛ إذا انكشف توكن فألغِه عبر BotFather واستبدله في Secrets.

## تعديل قائمة المراقبة

افتح `config.json` باستخدام زر القلم على GitHub:

- `drop_percent`: حد الانخفاض، 15 افتراضيًا.
- `pages`: عدد صفحات الاكتشاف، 50 منتجًا في الصفحة. زيادته تزيد استهلاك الوقت والطلبات؛ ابدأ بالقيمة الحالية.
- `pinned_handles`: أجزاء روابط المنتجات بعد `/products/`، دون `?variant=...`. يراقب البرنامج كل مقاسات وألوان المنتج. مثل `hog-dvts-003` على Dejavu؛ يجب أن ينتمي الرابط لنفس المصدر.
- `enabled`: إيقاف أو تفعيل المصدر.
- `priority`: ترتيب المعالجة، والقيم الأقل أولًا.

لا تضف متجرًا غير Shopify باعتباره مدعومًا تلقائيًا. نحتاج محولًا واختبار بيانات حقيقية له. لا تضع عناوين شخصية أو مفاتيح API في القائمة لأن المستودع عام.

## اختبارات وتشغيل محلي اختياري

```sh
python -m unittest discover -s tests -v
python watcher.py
```

الأمر الثاني يجمع الأسعار فقط، ولا يرسل رسائل. `--notify` يسمح بالإرسال عند توافر الأسرار. استخدم `--state` و`--report` لمسارات منفصلة للاختبار. البيانات المصطنعة في الاختبارات ليست أسعارًا تاريخية حقيقية ولا تُنقل إلى `data/`.

## موثوقية الحفظ والإرسال

الجولات متسلسلة لمنع تضارب الحالة. يسجل النظام التنبيه بعد نجاح Telegram فقط. **لا يوجد ضمان إرسال مرة واحدة تمامًا**: إذا وصلت الرسالة ثم انقطع التشغيل قبل حفظ الحالة على GitHub، قد تتكرر في جولة لاحقة. فشل `git push` يجعل التشغيل أحمر؛ استعد الحالة من Artifact إن لزم. التاريخ يبدأ من أول تشغيل فعلي، ولا يُستورد سجل قديم غير موثوق، ولا تتساوى المنتجات المختلفة لمجرد تشابه أسمائها.
